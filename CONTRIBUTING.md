# Contributing to RepoJourney

Thanks for helping make codebases easier to understand.

## Before opening a pull request

1. Open an issue for substantial product or architecture changes.
2. Keep each pull request focused on one outcome.
3. Include tests when behavior changes.
4. Avoid claims that cannot be connected to source evidence.
5. Run the validation commands before submitting.

```bash
npm run lint
npm run build
```

## Good first contributions

- improve keyboard navigation or accessibility;
- add a small static-analysis fixture;
- document a framework-specific route pattern;
- improve the Mermaid export;
- add a reproducible bug report.

Please be respectful, specific, and generous in review discussions.
